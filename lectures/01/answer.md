## 1. 基礎課題

### 実施内容

同じ質問を複数回実行し、モデルを変更した場合の回答内容と入出力トークン数の違いを比較した。

質問：

「AIE2026 の講座の宿題にある『3レベル』とは何ですか？」

使用したモデル：

- gemini-3.5-flash-lite
- gemini-3.8-flash

### gemini-3.5-flash-lite の結果

同じ質問を3回実行した。

- 1回目：入力22トークン、出力448トークン
- 2回目：入力22トークン、出力590トークン
- 3回目：入力22トークン、出力655トークン

3回とも、AIE2026の実際の宿題内容を正確には回答できなかった。

主に「基礎・応用・発展」という一般的な難易度分類を推測して回答していたが、2回目では「プロンプトエンジニアリングの深化レベル」や「AI・機械学習システムのレイヤー」など、別の可能性も提示された。

同じモデルに同じ質問をしているにもかかわらず、回答内容や文章量が異なり、出力トークン数にも448、590、655と差が生じた。

### gemini-3.8-flash の結果

同じ質問を3回実行した。

- 1回目：入力21トークン、出力614トークン
- 2回目：入力21トークン、出力681トークン
- 3回目：入力21トークン、出力602トークン

こちらも、AIE2026の実際の宿題内容を正確には回答できなかった。

「基礎・標準・発展」という一般的な難易度分類を中心に回答し、実際の課題にはないSOTAモデル、アンサンブル、Webアプリ化などの内容も提示された。

### 基礎課題の考察

両モデルとも、同じ質問をしても回答内容や出力トークン数が毎回異なった。このことから、LLMの生成結果には実行ごとの揺らぎがあることを確認できた。

また、gemini-3.5-flash-liteからgemini-3.8-flashへモデルを変更しても、AIE2026固有の「3レベル」を正確に回答することはできなかった。

両モデルとも、講座固有の情報を持っていない場合に、一般的なAI講座の知識をもとに、もっともらしい内容を推測して回答していた。

この結果から、モデルを変更するだけでは、モデルが知らない固有情報について正確な回答を得られるとは限らず、必要な情報をモデルに与える仕組みが必要であると考えた。

## 2. 実装課題

### 実施内容

`app/ask.py` を修正し、1回の質問で終了する処理から、会話履歴を保持したまま追加質問を続けられる処理に変更した。

元のコードでは `client.models.generate_content()` を使用して1回ずつ独立して質問していたため、前の質問や回答を引き継ぐことができなかった。

そこで、Google GenAI SDKの `Chat` を利用し、以下のようにチャットを作成した。

```python
client = genai.Client(api_key=get_api_key())
chat = client.chats.create(model=MODEL)
```

質問時には、従来の `generate_content()` ではなく、同じ `chat` に対してメッセージを送るように変更した。

```python
response = chat.send_message(question)
```

これにより、同じ `chat` の中で過去の会話履歴を保持しながら、追加質問を行えるようにした。

また、`while True` と `input()` を使用し、LLMから回答を受け取った後にユーザーが追加質問を入力できるようにした。

追加質問が入力された場合は会話を継続し、何も入力せずEnterを押した場合は `break` によってループを終了するようにした。また、入力を受け取れない場合に備えて `EOFError` の例外処理も追加した。

なお、実装にはGitHub Copilotを利用した。生成されたコードについて、`Chat`、`send_message()`、`while`、`input()`、`break`などの役割を確認し、処理内容を理解した上で動作確認を行った。

### 動作確認

実装後、gemini-3.5-flash-liteを使用して、以下のように連続して質問を行った。

1. 「LoRAとは何ですか？」
2. 「それを小学生にも分かるように説明してください」
3. 「今説明した技術のメリットを3つ挙げてください」

結果は以下の通りだった。

- 1回目：入力7トークン、出力596トークン
- 2回目：入力611トークン、出力463トークン
- 3回目：入力1087トークン、出力206トークン

2回目では「それ」としか指定していないにもかかわらず、モデルはLoRAを指していると判断し、小学生向けの説明を生成した。

さらに3回目でも「今説明した技術」としか指定していないが、LoRAのメリットを3つ回答することができた。

このことから、前の質問と回答が会話履歴として保持され、その内容を踏まえて後続の質問に回答できていることを確認した。

### 実装課題の考察

今回の実装を通じて、単にAPIへの質問を繰り返すだけではなく、同じ `chat` オブジェクトを使用することで、過去の会話を文脈として利用した対話ができることを確認した。

また、入力トークン数は7 → 611 → 1087と増加した。追加質問自体は短いにもかかわらず入力トークン数が増えていることから、会話を継続する際には過去の会話内容も文脈として利用されていることが確認できた。

一方で、会話履歴が長くなるほど処理する入力トークン数も増えるため、長い会話を扱う場合にはトークン数についても考慮する必要があると考えた。

今回の実装ではGitHub Copilotを利用したが、提案されたコードをそのまま使用するのではなく、それぞれの処理の意味を確認した。特に、`Chat`による会話履歴の保持と、Pythonの`while`、`input()`、`break`を組み合わせることで、対話型のLLMアプリケーションを実装できることを理解した。
